Daily carbon emission forecasting from 7-day rolling windows of environmental and
industrial sensor data. The project trains a **Transformer encoder** and a **1D CNN**,
benchmarks both against four classical and recurrent baselines, explains predictions
with SHAP, and ships the result as an interactive dashboard and a REST API.

Academic thesis project, SRM University.

## Results

The dataset yields 1,493 rolling windows, split chronologically into 1,193 for
training and 300 held out for test. All six models are evaluated on that same held-out
split. Numbers come from [`baseline_metrics.json`](carbon_cnn_project/baseline_metrics.json),
regenerated by `10_baseline_comparison.py`.

| Model | MAE | RMSE | MAPE (%) | R² |
|---|---:|---:|---:|---:|
| **LSTM** | **195.00** | **251.03** | **3.56** | **0.9832** |
| Linear Regression | 305.23 | 366.91 | 5.98 | 0.9640 |
| CNN | 350.34 | 423.80 | 7.64 | 0.9520 |
| Transformer | 412.84 | 492.59 | 8.03 | 0.9352 |
| Random Forest | 467.07 | 596.52 | 7.97 | 0.9050 |
| Simple Average | 1992.43 | 2173.06 | 39.32 | -0.2612 |

### On the Transformer not winning

The headline finding is negative, and it is reported as such. On this dataset the
LSTM leads, and plain **Linear Regression outperforms both deep sequence models**.

The reason is in how the data is generated. `02_data_synthesis.py` drives the
features with smooth AR(1) processes, so the target stays close to linear across the
observed range. A linear model captures nearly all of that structure, and the extra
capacity of an attention stack buys nothing it can use — the Transformer has more
parameters to fit and no additional signal to fit them to.

This is a property of the synthetic data, not evidence that attention is unsuited to
emission forecasting. Testing that claim needs a dataset with genuine non-linear
dynamics — regime shifts, threshold effects, interacting seasonality.

**If you change the data or retrain, re-run `10_baseline_comparison.py` and update the
table above before describing any model as best.**

## Architecture

Both models consume `(samples, 7, 6)` tensors — 7 days of history across 6 features
(`temperature`, `humidity`, `wind_speed`, `industry_level`, `vehicle_count`,
`energy_usage`) — and regress a single continuous `carbon_emission` value.

### Transformer encoder — `05b_transformer_model.py`

```
Input (7, 6)
  -> Dense(128) projection + sinusoidal positional encoding
  -> MultiHeadAttention(4 heads, key_dim=32) + residual + LayerNorm
  -> FeedForward(Dense 64 relu -> Dense 64) + residual + LayerNorm
  -> GlobalAveragePooling1D
  -> Dense(64, relu) -> Dropout(0.3)
  -> Dense(32, relu) -> Dropout(0.2)
  -> Dense(1, linear)
```

`d_model` began at 64 with 2 heads and underfit; widening to 128 with 4 heads lifted
held-out R² by roughly 0.011, averaged over seeds 42, 7 and 2024.

Ablations that made results **worse** and were rejected: `sqrt(d_model)` embedding
scaling, dropping positional encoding, `Flatten` in place of global average pooling,
pre-norm layer ordering, and adding a second encoder block.

### 1D CNN — `05_cnn_model.py`

```
Conv1D(64, k=3, relu, padding='same') -> BatchNorm
Conv1D(64, k=2, relu, padding='same') -> BatchNorm
Flatten -> Dense(64, relu) -> Dropout(0.3)
       -> Dense(32, relu) -> Dropout(0.2)
       -> Dense(1, linear)
```

No `MaxPooling1D` — a 7-step sequence is too short to compress spatially.

Both models train with Adam, Huber loss, and the same callbacks:
`EarlyStopping(patience=10)`, `ReduceLROnPlateau`, `ModelCheckpoint`.

### Preprocessing — `04_data_preprocessing.py`

- Trains on the single city with the most records.
- Features and target are standardized independently with `StandardScaler`.
- **Scalers are fit on the training period only**, then applied to the full series,
  so no test-period statistics leak into training.
- The split is **chronological at 80/20 with no shuffling** — shuffling a time series
  would let the model interpolate between neighbouring days and inflate every metric.
- Fitted scalers persist to `feature_scaler.save` / `target_scaler.save` and are
  required for any inference; predictions come out standardized and must be
  inverse-transformed.

## Setup

Requires Python 3.9 or newer.

```bash
git clone <your-repo-url>
cd Carbon-Emission

python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

pip install -r requirements.txt
```

`requirements.txt` platform-gates TensorFlow: macOS installs the Apple
`tensorflow-macos` and `tensorflow-metal` builds, while Linux and Windows get
`tensorflow-cpu`. The same file therefore works locally and on a cloud host.

## Running the pipeline

Scripts run in numbered order — each writes artifacts the next one reads.

```bash
cd carbon_cnn_project

python 02_data_synthesis.py       # city_day.csv        -> final_df.csv
python 03_eda_visualization.py    #                     -> eda_results.png
python 04_data_preprocessing.py   # final_df.csv        -> X/y_train.npy, X/y_test.npy, scalers
python 05_cnn_model.py            #                     -> best_cnn_model.keras
python 05b_transformer_model.py   #                     -> best_transformer_model.keras
python 06_model_evaluation.py     #                     -> metrics.txt, evaluation_results.png
python 08_explainable_ai.py       #                     -> shap_*.png, shap_values.csv
python 10_baseline_comparison.py  #                     -> baseline_metrics.json
```

The trained models and scalers are committed, so the apps below run straight from a
clone without retraining. After changing any script, re-run that layer and every
layer downstream of it.

## Running the apps

### Streamlit dashboard

```bash
python -m streamlit run carbon_cnn_project/07_streamlit_app.py
```

Five tabs: live prediction with feature sliders and a risk gauge; training evaluation
with interactive Plotly charts; model comparison and training history; SHAP
explainability with waterfall, radar and force plots; and a 7-day scenario forecast.
A sidebar selector switches between the Transformer and the CNN, and SHAP follows
whichever model is active.

The forecast tab is a **response-function probe, not a validated forecast**. It walks
the six drivers along a plausible weekly path — weekends are scripted with industry
level −2, vehicle count ×0.65 and energy ×0.70 — and plots how predictions move. The
weekend dip is therefore imposed by that scenario, not discovered by the model: the
dataset carries no day-of-week feature, so neither model can learn a workweek cycle.
Forecast accuracy is evidenced by the held-out metrics, not by this tab.

### FastAPI server

```bash
python -m uvicorn carbon_cnn_project.09_fastapi_server:app --reload
```

Swagger UI at `http://localhost:8000/docs`. Test it with the server running:

```bash
python carbon_cnn_project/09_test_api.py
```

The module path needs the `carbon_cnn_project.` prefix because the filename starts
with a digit and cannot be imported directly.

The server loads the Transformer as primary and falls back to the CNN. Note that
`/predict` accepts one data point and tiles it 7 times to build the `(1, 7, 6)`
input — it does not use real historical context, so its output is a sensitivity
probe rather than a true forecast.

## Deployment

The dashboard deploys to Streamlit Community Cloud for a free public link:

1. Push this repository to GitHub.
2. At [share.streamlit.io](https://share.streamlit.io), create an app pointing at
   `carbon_cnn_project/07_streamlit_app.py` on branch `main`.
3. Under **Advanced settings**, set the Python version to **3.11**. Newer versions
   have no wheels for the pinned `numpy` and `tensorflow-cpu`, and the build fails.

The free tier gives roughly 1 GB of memory and sleeps an app after 12 hours without
traffic, so the first visit after an idle period takes about 30 seconds to wake.

## Known issues

- **Windows console encoding.** Avoid emoji in `print` statements and file writes;
  the cp1252 default codec raises `UnicodeEncodeError`. Use plain text.
- **Digit-prefixed filenames.** Modules like `09_fastapi_server.py` cannot be
  imported with normal `import` syntax; use the dotted package path shown above.
